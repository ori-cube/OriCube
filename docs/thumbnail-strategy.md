# サムネイルの方式

v2（Cloudflare Workers + D1）で、作品一覧と SNS カード（OGP）の画像をどう作るかの判断。数字は鶴の作品（`apps/api/src/mocks/crane.ts`）で測った値。

## 結論

- **作品一覧**: 今の方式を続ける。投稿・更新のときにサーバーが完成形の図（JSON）を作って D1 に保存し、ブラウザで SVG にする
- **SNS カード**: 当面は「アクセス時に PNG を描いて 1 時間キャッシュ」のまま。作品やアクセスが増えたら、サーバーが描いた PNG を R2 に置く方式に切り替える
- **やらない**: ブラウザで 3D 表示を撮影した画像を受け取る方式。中身をサーバーが保証できない

## 今の仕組み

1. `createProcedureThumbnail`（`packages/engine/src/thumbnail.ts`）が、閲覧画面の最終状態を正面から平行投影し、面ごとの多角形・表裏・明るさを作る
2. 投稿・更新のとき、サーバーがこれを計算して `models.thumbnail` に JSON で保存する（`apps/api/src/summary.ts`）。要約の無い古い作品だけ、一覧のときに手順から計算する
3. 一覧では `OrigamiThumbnail`（`apps/web/src/components/OrigamiThumbnail`）が JSON から `<svg>` を組み立てる
4. SNS カードは `GET /api/models/:id/thumbnail.png` で、`renderThumbnailPng`（`apps/api/src/thumbnailImage.ts`）が 640px の PNG を描く。Workers の Cache API に 1 時間置く

| いつ | どこで | 何をする |
|---|---|---|
| 投稿・更新 | サーバー | 図の JSON を作って D1 に保存 |
| 一覧の表示 | ブラウザ | 保存済みの JSON から SVG を組み立てる |
| 投稿画面のプレビュー | ブラウザ | 向きを変えるたびに図を計算する |
| 自分の作品（`/me`） | ブラウザ | 作品ごとに手順の本体から図を計算する |
| SNS カードの取得 | サーバー | 手順から図を計算して PNG を描く（1 時間キャッシュ） |

## 方式の比較

| | A. 今の方式 | B. サーバーが描いて R2 | C. ブラウザで撮って R2 |
|---|---|---|---|
| 概要 | 図の JSON を D1 に保存。PNG はアクセス時に描く | 投稿時に PNG を描き R2 に保存 | 3D 表示を撮影してアップロード |
| 画像の信頼性 | 高い（サーバーが手順から描く） | 高い（同左） | 低い（任意の画像を送れる。検証が別途必要） |
| 見た目 | 平らな図（重なり順は近似） | A と同じ | 3D 表示と同じ |
| 一覧の速さ | 速い（画像のリクエストなし。API 約 5〜6 ms） | 1 ページで画像 24 枚を取得 | B と同じ |
| SNS 画像の負荷 | キャッシュ切れで再描画（キャッシュはデータセンターごと・1 時間） | 投稿・更新時に 1 回 | サーバー負荷なし |
| 更新の反映 | SNS 画像は最大 1 時間遅れる | すぐ | すぐ |
| 運用の手間 | D1 だけ | R2 と、更新・削除時の画像の後始末 | R2、署名付きアップロード、画像の検証 |

## 場面ごとの選択

- **トップの作品一覧**: A。図の JSON は 1 件約 5.5 KB で、手順の本体は読まないため、作品が増えても 1 ページの重さは変わらない
- **SNS カード**: A、必要になったら B。画像を取りに来るのはほぼ SNS のクローラーだけなので、今は再描画の負担が小さい
- **自分の作品（`/me`）**: A に寄せる。今は作品ごとに手順の本体を受け取ってブラウザで計算しているので、保存済みの図を返せば軽くなる

## 測った数字

| 項目 | 値 |
|---|---|
| 鶴の手順の本体（`procedure`） | 約 119 KB |
| 一覧用の図（`thumbnail`、72 面） | 約 5.5 KB |
| 図の計算 | 約 9 ms（投稿・更新時に 1 回） |
| 一覧の 1 ページ | 24 件（約 130 KB） |

一覧の総件数の数え上げとキーワード検索（部分一致）は、公開中の作品を全件読む。D1 は読んだ行数で課金されるので、作品が数千〜数万件になったら件数のキャッシュなどを検討する。
