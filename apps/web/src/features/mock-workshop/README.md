# v2 閲覧ページとモック作成画面

## 確認用 URL

`pnpm dev:api` と `pnpm dev:web` を起動して確認する。

- `/` と `/view` → `/view/crane`（折り方）
- `/view/crane?step=last`（同じ閲覧画面の最終ステップ・100%）
- `/view/blank-paper`（手順がない作品）
- `/view/unknown`（作品がない場合の404）
- `/post`（モック作成画面）

旧 `/v2/*` のURLは引き継がない。v2 の表示部品は `apps/web/src/components/OrigamiViewer`。

## データの取得

閲覧ページは Hono RPC で `GET /api/models/:id` を呼ぶ（`apps/web/src/apiClient.ts`）。APIは保存済みの値を `origamiModelSchema` で検証してから返す（`apps/api`）。作品の取得元は保存契約が決まるまで `apps/api/src/mocks/models.ts` のモック。

| フィールド | 意味 |
| --- | --- |
| `id` | `/view/[id]` で使用する作品 ID |
| `name`, `description`, `color` | 表示用の作品情報 |
| `procedure` | 投稿側の `exportProcedureV2` が返す `ProcedureV2` をそのまま使用 |
| `stepDescriptions` | 任意。裏返しを含まない折りステップ順の説明文 |

見つからない作品は 404、取得エラーは再試行できるエラー表示にする。モックの `crane.ts` はユーザーがUIで折って書き出した `crane.json` の履歴から生成した答えデータ。尾・首を起こし、両翼を150度で仕上げてから頭を折る。折り線・角度・表裏を記録どおりに保存し、中割り折りの重なり順の修正だけを再エクスポートで反映する。`apps/api/src/mocks/crane.test.ts` で全手順の投稿側の表示座標と完成形の各レイヤーを比較する。閲覧時にはソルバを実行しない。

## 裏返しとステップ番号

V2 の `history[].viewFront` の切り替えから裏返しを挿入する。モックは折り15回と裏返し6回の計21ステップ。説明文は `sourceIndex` で折りステップへ対応付ける。

裏返しで形状は変化せず、表示全体が Y 軸周りに180度回る。折りの前後で表裏が変化しない視点操作や、最後の折り以降の視点操作は保存されていないため表示できない。明示的な flip を保存する拡張が必要になった場合は投稿側とデータ型も合わせて変更する。

## 操作と検証

- 再生・一時停止・横一列のスライダー・同じ手順の繰り返しを下端の操作帯に配置
- 作品名・ステップ番号・説明を上部に表示し、同じ説明を重複させない。倍率と視点リセットはビュー右上へ配置
- 最初・前・数字3枠・次・最後の固定幅ページネーション。狭い画面でも同じ配置
- 自動再生と同じステップの繰り返しは文字付きチェックボックスで設定
- ステップ移動時の自動再生を選択可能（初期状態はオフ）。オンでも手順は自動で進めない
- 完成形は最終ステップの100%で確認。別の表示モードは持たない
- ドラッグ、キャンバス上の矢印キー、拡大/縮小と虫眼鏡付きの現在倍率、文字付きの視点リセット
- 動きを減らす設定では再生ボタンで終点へ切り替え、繰り返しを無効化。自動再生を選択した場合もステップ移動時にアニメーションせず終点を表示
- 非表示中の再生を停止し、離脱時にフレームと描画資源を破棄

実装の検証コマンド:

```sh
pnpm exec vitest run
pnpm --filter @oricube/design-system typecheck
pnpm exec tsc --noEmit --incremental false
pnpm exec next lint
pnpm exec storybook build
```

ブラウザでは全21ステップの0%/100%、各操作種類の中間位置、最後から最初への移動、320px幅、キーボード操作、reduced motion、WebGLエラーと再試行を確認する。

## UIで鶴のモックを作る

1. `/post` を開く。白紙から頂点をドラッグし、重なる場合は枚数・折り方を選んで「折る」で確定する。翼の仕上げ角度も選択できる。
2. 「元に戻す」「やり直す」「裏返す」「ビューモード」は既存のV2投稿UIを使う。操作中は保存・別データの読み込み・確認画面への移動を止める。
3. 確定済みの手順・紙の色・作品名・現在の表裏は、このブラウザのlocalStorageに保存する。読み込みに失敗した下書きは自動で上書きしない。ブラウザのデータ削除に備えて「JSONを保存」で `crane.json` を手元にも保存する。
4. 「JSONを読み込む」で再開できる。V2の履歴を検証して現在のエンジンで答えデータを再生成する。座標はデバッグ出力のように丸めない。取り込みに失敗しても現在の手順は残る。
5. 「折り方を確認」「完成形を確認」で、いま折ったデータを `OrigamiViewer` に渡す。確認画面から「折る画面に戻る」で続けられる。既存の鶴モックへのリンクは表示しない。
6. 完成したらJSONを共有するか、「モック用TSを保存」で `recorded-crane.ts` を保存する。

TSをモックへ組み込む場合は `apps/api/src/mocks/recorded-crane.ts` に置き、`apps/api/src/mocks/models.ts` で `recordedCraneModel` をインポートして `models` の鶴の要素を置き換える。作品名・色・答えデータ・履歴が一緒に入っている。新しい手順に対する説明文は任意の `stepDescriptions` として追加する。

この作成画面はAPI・DBへ送信しない。自動保存されるのは確定済みの折りのみで、選択中・アニメーション途中の折りは保存しない。V2の保存形式にある `history[].viewFront` から再生時に裏返しを挿入するため、折りと折りの間の往復の裏返しや、最後の折り後に行った裏返しは閲覧ステップにはならない。JSONに追加した `editorViewFront` は編集画面の再開時に使う。
