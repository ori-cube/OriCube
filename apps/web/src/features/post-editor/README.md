# v2 閲覧ページと投稿画面

## 確認用 URL

`pnpm dev:api` と `pnpm dev:web` を起動して確認する。

- `/` と `/view` → `/view/crane`（折り方）
- `/view/crane?step=last`（同じ閲覧画面の最終ステップ・100%）
- `/view/blank-paper`（手順がない作品）
- `/view/unknown`（作品がない場合の404）
- `/post`（投稿画面）

旧 `/v2/*` のURLは引き継がない。v2 の表示部品は `apps/web/src/components/OrigamiViewer`。

## データの取得

閲覧ページは Hono RPC で `GET /api/models/:id` を呼ぶ（`apps/web/src/apiClient.ts`）。APIは保存済みの値を `origamiModelSchema` で検証してから返す（`apps/api`）。作品の取得元は保存契約が決まるまで `apps/api/src/mocks/models.ts` のモック。

| フィールド | 意味 |
| --- | --- |
| `id` | `/view/[id]` で使用する作品 ID |
| `name`, `description`, `color` | 表示用の作品情報 |
| `procedure` | 投稿側の `exportProcedureV2` が返す `ProcedureV2` をそのまま使用 |
| `stepDescriptions` | 任意。裏返しを含まない折りステップ順の説明文 |
| `presentation` | 任意。完成形を見せる向き（`{ rotation: [x, y, z, w] }` の単位クォータニオン）。閲覧の最後に「完成形の向きに整える」ステップを足す |

見つからない作品は 404、取得エラーは再試行できるエラー表示にする。モックの `crane.ts` はユーザーがUIで折って書き出した `crane.json` の履歴から生成した答えデータ。尾・首を起こし、両翼を150度で仕上げてから頭を折る。折り線・角度・表裏を記録どおりに保存し、中割り折りの重なり順の修正だけを再エクスポートで反映する。`apps/api/src/mocks/crane.test.ts` で全手順の投稿側の表示座標と完成形の各レイヤーを比較する。閲覧時にはソルバを実行しない。

## 裏返しとステップ番号

V2 の `history[].viewFront` の切り替えから裏返しを挿入する。モックは折り15回・裏返し6回・完成形の向きに整える1回の計22ステップ（鶴は Z 軸周りに135°回して立てる）。説明文は `sourceIndex` で折りステップへ対応付ける。

裏返しで形状は変化せず、表示全体が Y 軸周りに180度回る。折りの前後で表裏が変化しない視点操作や、最後の折り以降の視点操作は保存されていないため表示できない。明示的な flip を保存する拡張が必要になった場合は投稿側とデータ型も合わせて変更する。

## 操作と検証

- 再生・一時停止・横一列のスライダー・同じ手順の繰り返しを下端の操作帯に配置
- 作品名・ステップ番号・説明を上部に表示し、同じ説明を重複させない。倍率と視点リセットはビュー右上へ配置
- 最初・前・数字3枠・次・最後の固定幅ページネーション。狭い画面でも同じ配置
- 自動再生と同じステップの繰り返しは文字付きチェックボックスで設定
- ステップ移動時の自動再生を選択可能（初期状態はオフ）。オンでも手順は自動で進めない
- 完成形は最終ステップの100%で確認。別の表示モードは持たない
- ドラッグ、キャンバス上の矢印キー、拡大/縮小と虫眼鏡付きの現在倍率、文字付きの視点リセット
- 動きを減らす設定では再生ボタンで終点へ切り替え、繰り返しを無効化。自動再生を選択した場合もステップ移動時にアニメーションせず終点を表示
- 非表示中の再生を停止し、離脱時にフレームと描画資源を破棄

実装の検証コマンド:

```sh
pnpm exec vitest run
pnpm --filter @oricube/design-system typecheck
pnpm exec tsc --noEmit --incremental false
pnpm exec next lint
pnpm exec storybook build
```

ブラウザでは全22ステップの0%/100%、各操作種類の中間位置、最後から最初への移動、320px幅、キーボード操作、reduced motion、WebGLエラーと再試行を確認する。

## 折る画面の構成

閲覧画面と同じ配置にそろえ、折る作業に必要なものだけを紙の周りに置く。

- 全面がキャンバス。背景は `--background-subtle` の作業台にして、白い裏面の紙も背景と区別する
- 左上に作品名・記録した折りの回数・次にすることの案内（待機・折り方の選択・アニメーション中・回して確認でそれぞれ変わる）
- 下端に操作帯。閲覧画面の「前へ」「次へ」の位置に元に戻す・やり直す、中央に裏返す・回して確認
- 頂点を離して折り方を選ぶときは、操作帯の中央が選択パネルに替わる。紙と折り線を覆わないよう枚数・角度・確定を横一列に並べ、表示と同時に「折る」へフォーカスする（Enterで確定、Escapeで取りやめ）。重なりがなければ枚数は出さない
- 作品名・紙の色・確認・白紙に戻すは右端の引き出し「作品の設定」へまとめる
- 確認画面は閲覧ページと同じ `OrigamiViewer` を表示し、上部の帯から折り方/完成形の切り替えと折る画面への復帰ができる

選択肢の切り替えには design-system の `SegmentedControl`、表示モードの切り替えには `Button` の `selected` を使う。

## 下書きの自動保存

確定済みの手順・紙の色・作品名・説明・完成形を見せる向き・現在の表裏を、このブラウザの localStorage に自動で保存し、次に `/post` を開いたときに続きから折れるようにする（`draft.ts`）。選択中・アニメーション途中の折りは保存しない。読み込みに失敗した下書きは上書きせず、「白紙に戻す」で保存を再開する。復元時は V2 の履歴を検証し、現在のエンジンで答えデータを作り直す。`editorViewFront` は編集を再開するときの表裏に使う。

V2 の保存形式にある `history[].viewFront` から再生時に裏返しを挿入するため、折りと折りの間の往復の裏返しや、最後の折り後に行った裏返しは閲覧ステップにはならない。

## 投稿

「作品の設定」の「投稿へ進む」から投稿画面（`PublishScreen.tsx`）を開く。1回以上折るまでは押せない。

1. 完成形を回して（ドラッグ・矢印キー・ホイール/ピンチ）、点線の枠の中に写る向きで「この向きで撮影」する。初期の倍率は完成形の外接球が枠の約75%になる値
   - カメラは上下が固定で、周りを回る・見下ろす・見上げるしかできない。対角線で折る鶴のように斜めに置かれた作品は、枠の下の「左に回す」「右に回す」（15°ずつ）で作品を画面内で回して立てる。初期の視点は正面で、正面のまま立ててからドラッグで角度をつける
   - 回すのはカメラではなく作品（閲覧シーンの `rotateModel`）。軸は見ている方向を水平に寄せた向きなので、作品の上下を真上に合わせられ、立てたあとの左右のドラッグでも傾かない。「向きをリセット」で開いたときの向きに戻る
   - 撮影した瞬間の作品の向き（カメラの角度は含まない）を、完成形を見せる向き（`presentation`）として下書きと作品に保存する。回していなければ保存しない。閲覧ページは最後に「完成形の向きに整える」ステップでこの向きへ回す（`apps/web/src/components/OrigamiViewer/README.md`）
2. 作品名（必須）・説明を入力して「投稿する」
3. 作品を `pending` で作成 → サムネイルをアップロード先へ直接 PUT → 公開APIで確定（`publish.ts`。流れは `apps/api/README.md` のサムネイル）
4. 完了画面から作品ページへ移動するか、白紙から新しく折る。下書きは投稿後も残す

- サムネイルは 640px 四方の PNG。背景を作業台の色（`--background-subtle`）で塗りつぶす（OGP は透過を扱えない表示先がある）
- 撮影は `OrigamiCanvas` の ref（`capture`）で、閲覧シーンの視点のままビュー中央の正方形（短い辺に合わせた枠）と同じ範囲を描く。縦長のビューでは縦の視野角を枠の幅に合わせて狭める。描画した直後に同じタスクで画像にするため `preserveDrawingBuffer` は使わない
- 途中で失敗したら、同じ内容の再試行では作品を作り直さない。撮り直し・アップロード先の期限切れ・保存先の拒否ではアップロード先だけを作り直す。内容を変えたら別の作品として作る（残った `pending` は API 側の掃除で消す想定）
- ログインの画面はまだない。未ログインで投稿すると、ログインが必要なことと下書きが残ることを伝える。`pnpm dev:api` では開発ユーザーでログインしている扱いになる
